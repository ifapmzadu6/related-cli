# Codex editing A/B pilot — 2026-08-16

This pilot ran Codex CLI 0.147.0 once per arm on three historical tasks from
`ifapmzadu6/too_tired_to_type`. Each run started at the parent of the target
commit in a disposable worktree. The treatment arm had to run
`related-cli@0.4.0` first; the control arm could use ordinary source search but
not co-change or history-based related-file lookup.

## What happened

The history-padding task is the positive case. Both arms produced the same
three-file implementation, while the treatment used 40.7% fewer non-cached
input tokens and finished 43.7% faster.

The icon-size task is the important failure. Querying the settings screen ranked
the corresponding Android settings screen first, but did not return either
notification-history screen in the top 10. It did return the iOS history screen
at rank 8. The agent treated that historical hint too strongly and changed the
history headers instead of the notification headers. The control arm used direct
search and reproduced all four expected edits.

Both API arms implemented the required body limit, sequential token/IP limits,
hashed token keys, fail-closed behavior, and non-identifying analytics. Both
passed four implementation-independent hidden acceptance tests. Neither copied
the historical patch's separate rate-limit module or generated binding-type
update, so file recall was below 100% even though the tested behavior passed.

The repository's full API integration suite could not be used as the hidden
check because the initially shared Wrangler runtime was older than the checkout's
compatibility date. A focused Vitest fixture without the integration server was
used instead. Treatment runs also saw an initial npm network failure inside the
Codex sandbox before a retry succeeded, which can inflate treatment time and
tokens.

## Conclusion

This pilot does not support enabling co-change results as an authoritative edit
plan. It shows one large efficiency win, one quality regression, and one roughly
neutral functional result. The safer product behavior is to present `related`
as an additional discovery channel and require the agent to reconcile its output
with explicit task nouns, direct search, and tests before choosing files.

Three tasks and one run per arm are too small for a general causal claim. More
repositories, repeated runs, and issue-level tasks are needed before claiming an
agent-success improvement.

The known icon-size failure was run once more after adding explicit-scope
guardrails to the treatment instructions. See the
[guardrail follow-up](2026-08-16-guardrail-follow-up.md).
